# DRV1-12 开发计划：强制真实 LLM 与最终工作流验收

日期：2026-08-25（Asia/Shanghai）

## 验收标准

1. `POST /daily-reviews/run` 接受 `requireLlmSuccess=true`，并把该要求持久化到操作输入，异步恢复后也不丢失。
2. 强制模式下，LLM 未配置、请求失败、超时、结构非法、数值越权或证据引用越权时，规则结果和失败证据可以保存，但 DailyReviewRun 与 Operation 必须为 `failed`。
3. 最终验收轮必须只有一次真实 LLM 请求，`status=available`、`source=llm`、`attemptCount=1`；确定性价格、均线、网格价格和数量不由 LLM 计算。
4. LLM 输入只包含最小白名单投影；输出只能引用本轮标的与证据，叙述不得加入阿拉伯数字或新交易事实。
5. 真实工作流覆盖当前六项持仓；每项读取真实行情源最近 30 个完整交易日并独立复算 MA5/MA10/MA30。
6. 每项成功资产保存即时与条件买回两个 GridPlan；所有草案符合价格步长、整手、共享预算、父卖单绑定和当日有效期规则。
7. 601127、600276、159851、513770 在最新每日复盘页逐项给出可用档位，或在收盘后给出不可交易的明确事实阻断。
8. 仓位、交易流水和外部委托观察在工作流前后哈希不变；系统不连接券商、不创建真实订单。
9. 最终页面由当前源码服务打开到最新 reviewId；DAG、结论摘要、四重点卡片、双清单、走势图和完整台账可见。

## 详细开发步骤

1. 扩展运行请求、Operation 输入和执行恢复路径，贯通 `requireLlmSuccess`。
2. 缩减 LLM 白名单输入并强化严格 JSON 合同，使供应商一次返回可验证的中文摘要。
3. 将 LLM 强制失败纳入复盘、操作、数据质量、告警与前端反馈语义。
4. 更新合同测试和真实 E2E，使最终模式明确要求真实 LLM 成功。
5. 重启当前源码后端，运行一次全新真实复盘，独立核验行情、均线、双网格、LLM 和受保护表。
6. 完成 PRD 规格检视、验收报告、追踪矩阵和最终停止原因审计；最后打开最新页面。

## 打回条件

真实 LLM 为 fallback、调用次数超过一次、行情为 mock/fixture、任一均线不一致、双网格缺失、条件买回无父卖单、即时买单超过组合预算、收盘后仍出现有效草案、受保护表漂移或页面与持久化草案不一致，均不得通过本阶段。

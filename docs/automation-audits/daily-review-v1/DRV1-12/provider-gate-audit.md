# DRV1-12 供应商门禁审计

日期：2026-08-25（Asia/Shanghai）

## DeepSeek 结果

修复代理传输后，当前默认 DeepSeek 凭据返回 HTTP 402、`Insufficient Balance`。该外部账户不能用于强制成功验收，且系统没有将余额不足降级为通过。

## 本机可用替代路径

仅检查环境变量是否存在（未读取、打印或落盘密钥）后确认：本机还配置了 `MINIMAX_API_KEY`，没有 OpenAI 凭据。用户已明确要求使用真实 LLM 运行本工作流，因此使用这份既有本地授权凭据属于原任务范围，不新增外部账户或权限。

## 准入闭环

1. 先用全新单次最小白名单请求验证 MiniMax 可用性。
2. MiniMax 适配改用 Axios 单请求，关闭隐式代理和重试，保持“每轮至多一次”。
3. 只有最小请求通过严格 schema 后，才以明确环境选择启动最终源码服务并运行全量复盘。
4. 若 MiniMax 也不可用，阶段立即以外部供应商阻断停止，不尝试第三方或新凭据。

## 最小探针反馈与闭环

MiniMax 可连接并返回 JSON，但把 `anchorLogic`、`spacingLogic`、`sizingLogic` 表达为字符串数组。该差异不缺失内容；合同增加无损规范化：最多四段字符串按中文分号连接后再执行长度、数值、标的和证据校验。不会为缺失字段补写内容，也不会接受未知标的。提示同时明确输入列表为空必须输出空数组。

六持仓探针随后返回合法根对象但两组摘要为空。该形式不能满足内容验收，因此新增精确覆盖门禁：两组输出的 symbol 集合必须分别与 attentionCandidates 和 decisionAssets 完全一致，且不得重复、漏项或增加项；请求末尾同时附上必须逐项保留的 symbol 骨架。

## 官方接口事实核查

MiniMax 当前官方文档将 `chatcompletion_pro` 列为历史接口；OpenAI-compatible 当前端点为 `https://api.minimaxi.com/v1/chat/completions`，模型包括 `MiniMax-M2.7`，`max_completion_tokens` 上限为 2048。适配器据此迁移到当前端点，并剥离响应中公开说明可能出现的 `<think>` 段后再解析 JSON。来源：<https://platform.minimaxi.com/docs/api-reference/text-chat-openai>、<https://platform.minimaxi.com/docs/api-reference/text-openai-api>。

六持仓探针在旧的三十秒默认窗口内被取消。当前环境未显式配置 `FAMS_LLM_TIMEOUT_MS`；结合官方输出上限和模型生成速度，将默认窗口提升至九十秒，仍受十二万毫秒硬上限约束且不增加重试次数。

九十秒探针返回 3021 字符但不是完整 JSON，符合十二组逐字段解释触及 2048-token 硬上限的表现。禁止修补截断文本；LLM 逐项摘要改为仅覆盖用户明确要求的 601127、600276、159851、513770 四个重点标的，每个字段限制为十二个汉字、数组最多一项。六持仓的确定性行情、均线、基本面、网格和台账仍全部保留，不因 LLM 投影收敛而删减。

四重点同时生成关注摘要和订单解释仍触及硬上限。最终按职责拆分：LLM 只生成四重点消息/风险关注摘要；`orderExplanations` 必须为空。订单锚点、间距、仓位、预算、价格步长、父单绑定和调整比较均由确定性推导区完整展示，避免模型重复解释数值规则。

收敛后的输出已完整返回，仅一项 `reasons` 含五条而旧合同上限为四。该差异不涉及缺字段或越权事实；数组合同放宽到最多八条，仍受单项长度、标的集合、证据引用和数值叙述门禁约束，不对模型内容做静默删改。

首次正式轮仍因完成 token 上限失败，确定性六资产无错误。对比成功探针后继续最小化白名单：每个重点标的仅输入一条事实变化理由、一条估值理由/风险和一条证据引用；系统提示压缩，叙述限制为八个汉字。完整证据继续保存在报告和 DAG，不由 LLM 回传重复 URL 集合。

第二次正式轮得到完整四标的输出，但数值叙述门禁拒绝通过。为避免把数字转写或删改后伪装合规，继续从 LLM 白名单输入移除含数值可能性较高的策略结论、估值理由、推荐理由和网格摘要，只保留枚举状态、事实变化等级、阻断码及一条证据引用。校验增加仅含字段索引和数量的脱敏诊断。

第三次正式轮在 899 字符处正常结束但不是 JSON，且未触发 token 截断。解析器增加脱敏括号/语法诊断，并仅允许两种无损规范化：移除对象或数组末尾多余逗号、解开一次双重 JSON 字符串编码。不得补括号、补字段或猜测截断内容；规范化方式随成功结果保存。

为降低供应商随机标点错误，提示末尾增加完整 JSON 骨架，预置四个允许的 symbol 和每项唯一 evidenceRef；模型只能替换叙述占位文字。本地新增占位符拒绝门禁，任何仍含“待填写/请填写”的输出不得标记 available。

首个通过门禁的正式轮内容复核发现“基本面料有变化”存在中文歧义。增加固定错词规范化 `基本面料有变化 → 基本面变化`，只作用于叙述字段，并在 `contentNormalizations` 留痕；不得改变事实等级、证据引用或任何数值。该轮不作为最终页面，需重新运行 E2E。

# DRV1-12 开发前审计

日期：2026-08-25（Asia/Shanghai）

## 当前基线

- 确定性行情、均线、双网格、组合预算和收盘门禁已完成真实数据验收。
- LLM 每轮至多调用一次且已有 schema、标的、证据引用和数值越权校验；供应商失败时会保存可审计 fallback。
- 现有运行请求尚未贯通 `requireLlmSuccess`，因此 fallback 仍可能伴随 `completed`，不满足本阶段最终验收。
- 上一轮真实供应商已发起一次请求，但返回 `llm_schema_invalid`；不能把该轮作为强制成功证据。

## 审计意见与闭环设计

1. **致命：强制 LLM 标志未参与最终状态。** 标志写入 Operation.inputJson，执行时从持久化输入读取；LLM 非 available 时强制 Run/Operation 为 failed。
2. **重大：供应商一次输出结构不稳定。** 只发送最小字段投影，系统提示明确每个数组项和空数组要求，限制输出长度与标的范围；仍只调用一次，不增加隐式重试。
3. **重大：不能用结构“修补”伪造真实成功。** 对供应商原始 JSON 继续执行严格 schema 校验，不自动补齐缺失叙述字段；非法即 fallback/failed。
4. **重大：失败不能污染资产错误计数。** LLM 门禁作为独立 `llmGate` 数据质量项和操作失败摘要保存，不伪装成某只资产失败。
5. **重大：页面按钮必须使用最终规格。** 每日复盘页面发起的人工运行默认传 `requireLlmSuccess=true`；调度器和其他既有入口保持向后兼容，除非显式要求。
6. **重大：最终运行发生在收盘后。** 保留 `session_closed`，不得为满足“具体买卖单”而生成已过期订单；四标的页面以明确阻断作为合规回答。
7. **重大：真实验收不得沿用旧轮。** 使用新幂等键生成新 reviewId，E2E 要求 `llmSynthesis.status=available` 并重新核验全部行情和持久化证据。

## 准入结论

一项致命和六项重大意见均有明确代码与自动验收闭环；无未解决准入风险，允许进入 DRV1-12 实质开发。

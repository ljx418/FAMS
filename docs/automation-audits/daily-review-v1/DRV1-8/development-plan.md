# DRV1-8 当日真实数据复盘与静态 HTML 交付计划

日期：2026-08-24（Asia/Shanghai）

## 验收标准

1. 复盘必须覆盖默认用户的 6 个非现金持仓，状态为 `completed`，不得以虚构结论填补失败标的。
2. 每个标的必须包含本轮行情、最近 30 个完整交易日收盘价、MA5/MA10/MA30 和可视化走势图；均线需独立重算一致。
3. 组合总值、持仓权重、现金底线和网格容量必须使用本轮报价统一计算，不能混用上次持仓行情快照。
4. 消息面和基本面只陈述项目事实集或交易所/基金管理人可核验事实；证据超时必须显式降级并阻止确定性加仓。
5. 买卖单只作为人工计划草案展示，价格、数量、金额、有效期和推导依据必须与数据库 `GridOrderDraft` 一致；禁止创建券商订单。
6. 交付一个无外部 CDN、可离线打开、响应式的简洁 HTML；首屏给出具体结论，深层数据可展开，并提供项目 DAG 工作台深链。
7. 完成数据库完整性、受保护业务表不变性、接口合同、前后端构建和浏览器运行时检查，并保存审计结果。

## 开发步骤

1. 建立运行前数据库备份、完整性结果和受保护表基线。
2. 强制刷新真实日线和本轮报价，运行当日开盘后复盘。
3. 修正实时组合定价口径；为慢外部事实适配器增加可审计的缓存降级，不允许整标的静默丢失。
4. 重跑直至六个标的完整进入报告，再做 MA、权重、网格和执行边界独立校验。
5. 汇总交易所/基金管理人证据，生成事实约束摘要、静态 HTML 和真实性审计 JSON。
6. 运行后端、前端和浏览器端验收；复核 PRD 追踪矩阵并记录剩余限制。

## 打回条件

- 任一持仓缺失、使用回退行情而未标注、均线重算不一致、组合总值不平、订单与数据库不一致、执行门禁解锁、官方证据与摘要冲突，均打回开发阶段。

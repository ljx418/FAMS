# DRV1-11 开发前审计

日期：2026-08-25（Asia/Shanghai）

## 当前基线

- 页面已有结论摘要、即时订单单表、受控关注摘要和五段确定性推导。
- 后端报告已保存 `grid + buybackGrid`，但前端只读取 `orders`，条件买回在页面不可见。
- 真实最新复盘发生在收盘后，四重点标的均应显示 `session_closed`，而不是空白或过期价格。
- 页面底部旧网格表只处理即时 `asset.grid.orders`，没有类型与父子状态。

## 审计意见与闭环设计

1. **重大：条件单可能和即时单混淆。** 采用两张独立表、不同背景色、不同动词和独立复制按钮；条件表状态固定解释为“父卖单成交后再设置”。
2. **重大：用户问题要求四标的逐项回答。** 固定代码顺序建立重点卡片，从已保存决策摘要读取，不做页面端新计算。
3. **重大：收盘后空表容易被误解为系统失败。** 重点卡片和即时清单上方展示可读阻断；`session_closed` 翻译为“今日已收盘，请下一交易时段重新运行”。
4. **重大：条件买回缺父单说明。** 只读取保存的 triggerCondition，显示父卖档、父卖价和要求成交数量；缺字段时标为不可核对而不猜测。
5. **重大：推导链缺新约束。** 增加 tick、方向取整、组合预算前后、session close、最大余数以及条件公式区域。
6. **重大：历史兼容风险。** 所有 `conditionalBuyback`、tradingRules 与 validity 均使用空安全默认值，旧报告保持现有页面。

## 准入结论

六项重大意见都有可测试闭环；无未解决致命意见，允许进入 DRV1-11 实质开发。

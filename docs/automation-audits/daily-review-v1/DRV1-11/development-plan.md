# DRV1-11 开发计划：每日复盘双网格与四重点标的页面

日期：2026-08-25（Asia/Shanghai）

## 验收标准

1. 页面顶部固定展示 601127、600276、159851、513770 四项重点标的；每项显示最新价、即时买点、即时卖点、条件买回点或明确阻断原因。
2. “现在可人工设置”只包含 `proposed` 即时 GridOrderDraft；“卖出成交后再设置”只包含 `awaiting_parent_fill` 条件买回，文案不得暗示条件单现在即可挂单。
3. 两类清单分别支持复制；条件清单必须带父卖档、父卖价和“成交后激活”说明。
4. 无订单时不能只显示空状态，必须把 `session_closed`、证据、预算、仓位或整手阻断翻译为可读中文。
5. 推导折叠项展示交易步长、方向取整、整手/最大余数、组合预算前后值、当日有效期和条件买回公式。
6. 旧版历史报告没有 `buybackGrid` 时安全降级，不出现运行时错误。
7. DAG 网格节点分别统计即时计划、条件计划、即时草案和待父单成交草案。
8. 前端构建、静态合同、四视口浏览器运行时验收均通过；页面不展示模型私密思维链。

## 详细开发步骤

1. 扩展 DailyReviewWorkflow 网格节点的分类输出。
2. 重构 DailyReviewDecisionPanel：增加四重点卡片、双表格、双复制动作和阻断翻译。
3. 扩展推导内容和响应式样式；将重点卡片与历史详情安全兼容。
4. 更新 DailyReviews 底部原始网格表，使即时与条件类型可辨，避免重复且语义冲突。
5. 扩展前端静态/运行时验证脚本，随后在当前源码端口进行真实页面验收。

## 打回条件

任一重点标的缺失、条件单混入即时清单、条件买回脱离父卖单、收盘后出现“现在挂单”误导、旧报告崩溃、页面订单与数据库草案不一致，均打回开发阶段。

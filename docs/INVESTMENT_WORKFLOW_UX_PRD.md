# FAMS 三类资产策略与统一复盘 PRD

版本：1.0
状态：受控开发中
更新时间：2026-09-15

## 1. 产品目标

在保留现有按功能划分导航和专家页面的前提下，用“基本信息确认 -> 仓位策略 -> 回测复盘”解释各模块关系，并让普通用户在每个页面先看到数据状态、结论、人工计划和下一步。系统不改造成强制向导，也不删除专家入口。

本阶段只交付研究、观察、比较和人工计划草案。固定保持：

```text
formalTradingUnlocked=false
autoTradeUnlocked=false
canCreateOrder=false
orderCreateAllowed=false
```

## 2. 资产与账户口径

| 账户 | 主要资产 | 默认策略建议 |
| --- | --- | --- |
| 同花顺 | 行业 ETF、波动个股、红利低波股票/ETF | 系统建议 `rotation_volatility` 或 `dividend_low_vol`，用户确认后生效 |
| 支付宝 | 现金、黄金、债券、权益等组合标的 | `portfolio_policy` |

同花顺资产不能只凭股票/ETF 类型自动归类。系统必须说明建议理由，用户确认后才进入策略运行；未确认或冲突项保持 `unassigned`。

## 3. 三段工作流

### 3.1 基本信息确认

1. 用户在资产管理选择同花顺或支付宝，再上传持仓截图；同花顺可继续上传历史成交、普通委托和条件单。
2. 系统私有保存截图，经单次视觉同意后识别；用户逐行纠错或忽略，最终确认后才写入账户事实。
3. 用户确认后刷新最新可得价格和完整历史日线。页面展示最新价、provider、行情时点、延迟等级、最近 30 个完整收盘价及 MA5/MA10/MA30。
4. 内部至少读取 80 个完整交易日供 MACD、20 日量比和日频相对轮动使用。RRG 使用复权收盘价计算透明相对强度/动量，不得标称“日均价格 RRG”或官方 JdK RRG。
5. 产出在资产管理、仓位管理和交易记录中可见，并形成不可变研究输入快照。

### 3.2 仓位策略

#### 行业轮动与波动仓

- RRG 在行业内或同类 ETF 组内负责候选排序；不允许把不同资产类别混成同一排序集合。
- 新增买入研究必须同时满足：RRG 位于 `leading/improving`、`close >= MA30`、`MA5 >= MA10`、MACD 柱为正且不低于前一完整交易日。
- 成交量只确认突破质量；突破场景要求 `volumeRatio20 >= 1.2`。低流动性、行情过期、身份错配或事实证据重大变化直接阻断新增买入。
- ATR、价格步长、整手、现金与仓位约束负责网格定价和数量。
- 已有网格优先复核；只有策略失效、波动状态变化、重大事实变化或用户明确重算时创建新版本。

#### 红利低波

- 核心证据为股息率、三年分红、行业龙头、分红可持续、低波动、估值和风险。
- 页面默认只展示数据是否可信、候选结论、买卖观察区间、人工清单与失效条件。
- 数据不足或风险硬门槛失败时不得生成价格或数量；候选、淘汰原因、FIVD-R、滚动验证和原始证据进入高级视图。

#### 投资组合

- 支付宝在 2026-09-01 至 2026-12-31 使用高防御 `10/15/50/25`。
- 2026-12-31 后停止生成新草案；经用户一次确认后启用永久组合 `25/25/25/25`。
- 永久组合为股票、长期债券、黄金、现金各 25% 的研究模板，不得错误归因于 Ray Dalio。

所有策略只输出可供用户在外部平台手工设置的价格、数量、有效期、理由和失效条件；不创建、不提交订单。

### 3.3 回测复盘

`/backtest` 是唯一策略回测入口，包含“建议与实际复盘 / 投资组合回测 / 历史运行”三种模式；`/portfolio-comparison` 兼容重定向到组合回测模式。

建议类回测同时支持：

- `saved_advice_replay`：仅复核真实保存的 Advice/GridPlan。
- `point_in_time_simulation`：使用冻结策略版本和当日可见数据逐日重放，禁止未来数据泄漏。

每次比较固定输出：

1. `follow_advice`：下一可交易时点执行策略建议，计入费用、滑点、整手和可交易性限制。
2. `hold_without_action`：冻结期初持仓，不执行策略交易。
3. `actual_transactions`：按真实交易流水、费用、分红和公司行为逐笔回放；不能对平时必须为 `insufficient`。

输出累计收益、收益率、最大回撤、收益/回撤曲线、时间敏感性、已闭合建议胜率和期望盈亏。未闭合建议不进入胜率分母，必须单列数量。

## 4. 数据真实性与内容门禁

- 免费数据只能声明“最新可得并明确标时”，不得声明交易所授权实时行情。
- 盘中报价时点缺失或超过 15 分钟、完整日线落后超过一个交易日时，可以展示历史信息，但不得生成精确人工计划价格与数量。
- 行情、指标、建议和回测结果必须携带 `provider/asOf/snapshotHash/evidenceRefs/dataHealth`。
- LLM 只能整理确定性白名单事实，不参与价格、均线、RRG、网格、收益或风险指标计算；不得新增数字、标的或无证据事实。
- 基本面与消息变化只允许 `none/watch/material/insufficient`；没有证据不得推测“利好”或“基本面改善”。
- 历史回测必须使用 point-in-time 数据和冻结策略版本；缺失数据不能用当前值回填。

## 5. 页面体验

- 保留资产、仓位、交易记录、股票分析、红利低波、相对轮动、策略回测、任务等功能导航。
- 只移除重复的“持仓组合对比”导航项，旧 URL 继续兼容。
- 相关页面顶部展示轻量工作流状态条，说明当前步骤、缺口和下一页。
- 策略页首屏最多四个主要区块：数据状态、核心结论、人工计划、下一步；每个状态只显示一个主操作。
- provider、内部状态码、参数、原始候选与 evidenceRefs 默认折叠。
- 1440、768、390 像素下不得出现文字溢出、图表裁切或主要操作隐藏。

## 6. 出门标准

- 用户从确认截图到看到对应策略结果不超过六次主要操作，不含逐行纠错和外部网络等待。
- 三类资产归类、三类策略输出、旧网格复核、年度组合策略门禁和统一回测路径均有真实数据 E2E 证据。
- 三场景曲线来自同一冻结输入快照；实际流水不完整时诚实阻断。
- 页面和 ChatBox 对同一策略运行返回相同结论、Operation 与 evidenceRefs。
- 不允许 mock、seed 或静态 HTML 证据替代真实账户、真实行情和真实浏览器验收。
- 专家页面保留，四项交易权限始终为 false。

# target-architecture-gap.drawio 摘要

更新时间：2026-07-03

本 drawio 文件用于说明 FAMS 当前阶段的用户体验优化目标、当前架构与目标架构差异、体验解释层技术路径、红利低波用户路径、组合回测用户路径、ChatBox 第一公民 / PI AgentCore 业务入口、开发及验收计划、项目里程碑、验收门槛和出门条件。页数固定为 8 页，不超过 8 页。图内不使用无法落地的泛化模块，每个关键节点都绑定到真实页面、API、服务、数据/缓存、体验组件、AgentCore 适配器或审计 artifact。

当前阶段仍是正式交易 release 前置评审，不是正式交易 release。体验优化只能降低理解成本，不能隐藏数据缺口、模型不足和交易锁定。`dataTrustGrade=INSUFFICIENT` 时只能研究观察；`calculationAuditStatus=deterministic_replay_only` 只证明同一输入下公式复算一致，不证明模型有效或策略可交易。

2026-07-01 ChatBox 文档审计结论：当前 drawio 与配套文档可以支撑 ChatBox 第一业务入口 / PI AgentCore 集成进入代码实现阶段，但不能声明 ChatBox 第一公民完整能力已经完成。每个 CB 子阶段退出前仍必须生成审计包、执行 E2E、复核 PRD 规格和交易边界。

2026-07-02 ChatBox UX 主线补充：当前 ChatBox 功能链路已有基础，但体验仍偏技术化。下一阶段优先执行 CB-F / UX-7：任务式入口、普通话结果层级、数据健康提示、技术细节折叠、消息级操作和移动端可读性。该补充不扩大工具权限，不释放正式交易。

2026-07-02 双轨 UX 主线补充：下一阶段不是删除现有多 Tab / 多模块系统，而是建立“普通用户默认 ChatBox + 工作台、资深用户保留专家模块页”的双轨体验。普通用户通过 ChatBox 发起任务、在工作台看摘要、图表、数据可信和下一步；资深用户继续直接进入 DividendLowVol / Backtest / Operations / Audit 等页面使用筛选、排序、参数和完整证据。ChatBox、工作台和专家页必须共享同一 API、服务、审计包和交易 gate。

2026-07-03 实体状态补充：本 drawio 必须让人直接看出哪些实体已开发、哪些开发中需修改、哪些未开发待新增、哪些属于交易硬边界。ChatBox 是第一业务入口，不替代原多 Tab 专家系统；原专家模块继续作为资深用户深度入口，必须在图中与 ChatBox、工作台、API、服务、审计和 Gate 保持强关联。

2026-07-03 UX 基线检视补充：当前页面基础功能存在，但移动端侧栏挤压主内容、深蓝/深紫视觉过重、硬编码深色样式扩散、普通模式技术噪音过多、ChatBox 主任务入口不够强。drawio 第 2、6、8 页已补充移动端 Shell、design token、ChatBox 任务入口、普通话结构化回复、数据健康提示、截图审计和交易边界文案审计。该补充不改变业务代码，也不释放交易能力。

2026-07-03 ChatGPT 复核建议闭环：当前文档可以进入下一阶段实现，但不等于 ChatBox 体验已完成，也不等于正式交易可用。代码阶段必须按 UX-F0 到 UX-F6 顺序执行；UX-F0 必须先生成 1440px、768px、390px 基线截图；ChatBox 核心业务回复必须有 `answerLevel / summary / keyNumbers / nextActions / dataHealth / evidenceRefs / technicalDetailsCollapsed / prohibitedActions` 结构化协议；`DataHealthNotice` 必须覆盖 provider unavailable、SQLite risk、data insufficient、artifact missing、operation failed、validation blocker；`dual_track_ux_audit.json` 必须证明专家页仍可访问；`trade_boundary_wording_audit.json` 必须扫描 ChatBox 回复、按钮、确认卡、工作台、专家页、SUMMARY 和 E2E HTML 报告。

## 颜色规则

- 灰色：已经实现或本阶段已有基础能力。
- 黄色：开发中 / 需修改 / 体验或状态不达标的能力。
- 橘黄：未开发 / 待新增的体验解释、正式评审或 release 前置能力。
- 红色：交易硬边界或禁止事项。
- 蓝色：用户路径。
- 绿色：阶段输出、验收结果或允许出门状态。
- 紫色/蓝紫色：体验解释层，包括普通模式、专业模式、结论卡、术语解释和下一步操作。

## 分层关系要求

图内目标架构必须表达以下强关联，不允许只写抽象模块：

```text
用户自然语言 / 工作台动作
-> ChatBox UX 展示层与普通用户工作台
-> 原专家页面和现有 API
-> 策略服务、数据证据和 Operation
-> 审计产物与 Trade Gate
-> 普通用户可理解结果 + 专业用户可复核证据
```

## 页面结构

1. **目标体验与用户路径**：普通用户默认走 ChatBox + 工作台，看状态摘要、普通话结论、下一步和禁止动作；专业用户保留多模块专家页，可进入完整指标、validation 和审计 artifact。
2. **当前架构与目标架构差异**：按前端、API、服务、数据、审计/Gate 五层展示“当前基础 -> 需修改 -> 需新增 -> 硬边界 -> 用户体验结果”的强关联路径。
3. **体验解释层架构**：展示 `ExperienceModeToggle.tsx`、`PlainLanguageHelp.tsx`、`DividendLowVolDecisionCard.tsx`、`PortfolioBacktestSummaryCard.tsx`、`StrategyComparisonExplainer.tsx`、普通用户工作台和 Chat UX Presentation Layer 如何接入现有页面、API 和审计。
4. **红利低波用户路径**：展示状态摘要、Top 候选卡、买卖观察区间、数据可信、风险提示、人工计划草案和专业证据展开路径。
5. **组合回测用户路径**：展示策略选择、多时间段收益曲线、收益来源解释、数据等级、模型有效性、交易阻断和人工计划草案。
6. **开发及验收计划**：把 UX-1 到 UX-8 和 UX-F0 到 UX-F6 映射到实现实体、用户效果、审计产物和验收命令，其中必须先固定 UX 基线，再修复 ChatBox、移动端 Shell 和双轨工作台。
7. **里程碑与出门条件**：列出 M1 到 M4、当前可声明状态、当前不能声明状态、审计文档路径、截图验收和外部审计重点。
8. **ChatBox 与 AgentCore 业务入口**：说明 ChatBox 如何作为第一业务入口，通过 `FamsChatBox.tsx / chat.ts / famsChatService / chatLlmPlannerService / piAgentCoreAdapter` 串起业务查询、quick-run 回测、对话内图表、二次确认、Operation、页面跳转和交易阻断。

- 第 1 页：普通用户能通过 ChatBox + 工作台看懂系统当前能做什么、不能做什么、下一步做什么；专业用户能继续进入多模块专家页和证据详情。

- 第 8 页：审核者能看懂 ChatBox 第一入口目标、当前 v1 能力、CB-F UX 优化、PI AgentCore 后续目标、全业务工具权限分层、对话内图表、二次确认、Operation 联动、交易阻断和审计产物。

## 风险与备选路线

当前文档允许后续自动化开发继续推进 UX 优化，但不隐藏以下真实风险：

- 体验简化可能误导用户忽略数据缺口、模型不足或交易锁定。
- 普通模式如果只展示结论而不展示可信度，会形成虚假确定性。
- 专业模式如果被移除，审计和复核能力会倒退。
- 免费数据源、proxy benchmark 和 deterministic replay 仍不能作为正式交易 release 证据。

推荐路线：

```text
普通模式默认展示结论和下一步
+ 专业模式保留完整证据
+ 所有 blocker 永久可见
+ 截图和审计 JSON 双验收
```

该路线可以支撑 ordinary-user-ready 和 formal-review-ready；不能直接声明正式交易可执行。

# 子阶段4：证据API与前端工作台计划

## 验收标准

1. 页面用中文明确显示四态结论，`data_insufficient` 不得渲染为“策略无效”。
2. 展示预注册哈希、开发/冻结/前向区间、数据覆盖、样本、统计、经济、稳健性和前向逐项门禁。
3. 展示组合结果、简单/匹配/沪深300基线、8步消融、基础/2倍/3倍成本；缺数据时显示缺失原因，不填演示值。
4. 可启动交易决策级证据运行和前向影子运行；两者均只产生研究记录。
5. 所有按钮可键盘访问、状态不只靠颜色表达，窄屏可以阅读。
6. API和前端契约自动验证四个交易边界均为false。

## 详细开发步骤

1. 扩展Backtest API DTO，返回证据等级、四态结论、逐类JSON与Manifest。
2. 新增协议摘要和前向运行API，记录版本与观察状态。
3. 把“三年回测”升级为“证据与回测”工作台，增加结论卡、时间轴、覆盖漏斗、门禁表和前向卡。
4. 保留旧滚动窗口为研究参考并醒目标注，避免与交易决策级结果混淆。
5. 添加静态前端契约、API真实E2E、构建和可访问性检查。

## 开发前审计

- **重大风险：** 空证据若用0填充会被误读为真实0收益。所有经济和统计指标缺失时显示“未计算”，并同时显示阻塞原因。
- **重大风险：** 前向门禁通过可能被误读为策略已有效。页面明确要求历史全部门禁与前向门禁同时通过，前向运行自身仍不解锁交易。
- **一般风险：** 现有字段使用旧100笔/12月文案。全部替换为300笔/24月，并保留旧结果“仅研究参考”标签。
- **结论：** 风险已有文案、类型和状态硬门禁，无新增致命或未闭环重大问题，可开始开发。

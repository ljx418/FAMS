# 子阶段1：列式行情仓与数据质量开发计划

## 验收标准

1. Bronze/Silver/Gold 目录、Manifest、哈希、分区与幂等规则可机器校验。
2. 本地既有真实分钟数据可导出到Silver Parquet并由DuckDB读取，重复运行不增加重复行。
3. 免费BaoStock采集器支持日期/代码分片、恢复、限流、取消和逐分区质量报告。
4. 覆盖率以点时主板身份清单为分母，不以已缓存代码为分母。
5. 缺少DuckDB、PyArrow、provider或数据时返回明确阻塞原因，不回退日线代理。
6. 真实数据验收至少读取一个完整A股交易日并与当前规范表记录数核对。

## 详细开发步骤

1. 建立Python列式管道，使用本地已有BaoStock，并把DuckDB/PyArrow版本固定到独立requirements。
2. 定义Bronze原始文件、Silver 5m/1m、Gold特征的Schema和数据质量契约。
3. 实现SQLite现有5分钟表到Silver的无损导出，用于真实链路验收。
4. 实现免费全市场分片采集CLI；默认只做小样本，完整五年任务必须显式传入确认参数。
5. 实现Manifest/Profile命令并由后端数据就绪接口读取。
6. 补齐契约、幂等、覆盖率和真实读取测试。

## 开发前审计

- **重大风险：磁盘只剩约230GB。** 使用Parquet压缩、按年月/代码分区；禁止同时保留三份全量副本。
- **重大风险：公开源无SLA。** 免费数据只允许形成`quick_falsification`证据；正式晋级必须使用授权数据。
- **重大风险：BaoStock只有5分钟线。** 子阶段1只负责快速否证层；精确成交的1分钟数据契约在子阶段2强制。
- **结论：** 风险均有硬门禁与明确降级语义，无新增致命风险，可开始开发。

# 子阶段 3：人工买卖草案审计

## 开发前验收标准

1. 只从八步通过且时间/数据门禁有效的候选生成草案；无合格候选时返回明确原因而不是虚构草案。
2. 最多 3 只、单只总资产 10%、策略总额 30%、可用现金和 100 股整数手同时生效。
3. 入场限价为 `VWAP×1.002` 向下取最小价位；有效期不晚于 14:56:50。
4. 同标的已有持仓必须生成冲突，不能静默忽略。
5. 没有通过晋级门槛的样本外参数版本时，草案必须为 `observe_only`；用户复核不能把它变成真实订单。
6. 次日退出矩阵、成本模型、跳空/同线冲突/强制退出顺序完整展示并持久化。

## 详细开发计划

1. 实现纯资金分配函数和持仓/现金读取。
2. 实现草案创建、查询和人工“已阅/放弃”状态。
3. 将回测晋级状态接入草案可行动门禁。
4. 增加资金边界、整数手、冲突和交易隔离测试。

## 开发前审计意见

- **重大风险（已闭环）**：用户可能把“人工草案”误解为已下单；接口和页面不得出现“提交委托/执行买入”，只允许“标记已阅/放弃”。
- **重大风险（已闭环）**：没有经过样本外验证的退出参数不能成为默认建议；保留参数矩阵但 `selected=null`，草案仅观察。
- **重大风险（已闭环）**：总资产和现金不能从行情估算；以当前持仓账本的现金资产及持仓市值为准，缺失时阻断。

结论：无新增致命或重大未闭环意见，可以进入子阶段 3 开发。

## 完成后验收与 PRD 检视

- 资金分配契约测试通过：最多3只、单只不超过10%、合计不超过30%、现金上限与100股整数手均生效。
- 次日退出参数矩阵和既有成本模型逐项固化；没有晋级回测时 `selected=null` 且草案为 `observe_only`。
- 草案只支持“已阅/放弃”，不存在确认成交、提交委托或券商接口。
- 总资产、现金和同标的冲突均从当前真实持仓账本读取，账本不足时明确阻断。

**审计结论：通过。** 未发现重大规格偏差，可进入子阶段 4。

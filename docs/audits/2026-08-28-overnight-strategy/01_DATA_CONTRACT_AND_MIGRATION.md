# 子阶段 1：数据契约与迁移审计

## 开发前验收标准

1. PRD 将八条自然语言规则转成无歧义边界、时间、公式和缺失数据行为。
2. 分钟线使用独立数据表，唯一键包含代码、市场、时间周期、时间点和数据版本，不能污染现有日线唯一键。
3. 时间点股本事实保存披露日，查询必须满足 `publishedAt <= signalAt`。
4. 扫描、候选、草案、回测窗口与交易证据可审计；共享市场数据不会因用户删除而级联删除。
5. 交易边界字段硬编码关闭，模型内不存在券商委托标识或自动下单状态。

## 详细开发计划

1. 增加独立分钟原始/规范表与股本事实表。
2. 增加用户扫描、候选、草案和回测审计表，必要的大型证据使用 JSON 快照。
3. 增加索引、级联关系和 Operation 关联。
4. 生成 Prisma 客户端并执行 schema 验证；数据库应用前制作明确路径的备份。

## 开发前审计意见

- **重大风险（已闭环）**：现有 `MarketBarRaw/Canonical` 唯一键不含 `tradeTime/timeframe`，禁止复用来保存 5 分钟数据；采用独立表。
- **重大风险（已闭环）**：策略被用户称为“套利”，但不存在无风险保证；页面统一改称“隔夜强势策略”，仅以副标题解释来源。
- **重大风险（已闭环）**：历史市值若使用当前总股本会产生前视偏差；股本事实以披露时间查询。
- **致命风险（已闭环）**：项目正式交易尚未解锁；所有操作保持研究、观察、人工草案，拒绝创建订单。

结论：无新增致命或重大未闭环意见，可以进入子阶段 1 开发。

## 完成后验收与 PRD 检视

- Prisma schema 格式化、校验、客户端生成与 SQLite `db push` 均通过。
- 已建立独立 `MarketIntradayBarRaw/Canonical`，唯一键包含 `timeframe + barTime`；没有改动现有日线唯一键。
- `MarketShareFact.publishedAt` 为必填并建立代码/披露时间索引。
- 扫描、候选、人工草案、回测窗口与逐笔交易均有独立审计模型；用户删除只级联用户运行记录，不级联共享行情与股本事实。
- 数据库变更前已保存 `backend/prisma/dev.pre-overnight-strategy-20260828.db`。
- 数据模型没有真实订单、券商委托或自动执行关系。

**审计结论：通过。** 对照 PRD 未发现致命或重大规格偏差，可进入子阶段 2。

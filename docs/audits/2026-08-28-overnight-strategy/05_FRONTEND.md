# 子阶段 5：隔夜强势策略页面审计

## 开发前验收标准

1. 主导航新增“隔夜强势策略”，页面副标题明确“原隔夜套利八步法”并说明并非无风险套利。
2. 三个页签完整：今日八步筛选、人工买卖草案、三年策略回测。
3. 顶部时间门禁、数据截至时间、数据质量和交易隔离状态无需滚动即可看到。
4. 八步漏斗、候选指标、逐步输入/输出/作用、价格/VWAP与信号图均可交互；空结果解释原因。
5. 草案显示价格、数量、金额、资金限制、退出矩阵、推导依据与持仓冲突，只提供“已阅/放弃”。
6. 回测显示任务进度、覆盖率、样本量、晋级状态、指标、窗口和数据缺口；`insufficient` 不使用成功色。
7. 桌面与窄屏可读，图表具备文本摘要和键盘可达的候选选择。

## 详细开发计划

1. 建立完整 TypeScript API 契约和请求函数。
2. 实现时间/风险头部、八步流程卡、候选表与 ECharts 分时证据图。
3. 实现人工草案卡片、参数矩阵和复核交互。
4. 实现回测状态、覆盖率、窗口/交易表和轮询。
5. 接入路由与主导航，增加前端静态契约和构建验证。

## 开发前审计意见

- **重大风险（已闭环）**：用户原始话术带确定性收益暗示；页面标题和风险文案统一为方向性强势研究，不使用“锁死/必涨”。
- **重大风险（已闭环）**：空候选/不足回测容易被误认为故障；必须用阻断原因、数据时间和下一步修复建议解释。
- **重大风险（已闭环）**：草案按钮容易越界；只保留生成观察草案、标记已阅和放弃，不提供真实下单 CTA。

结论：无新增致命或重大未闭环意见，可以进入子阶段 5 开发。

## 完成后验收与 PRD 检视

- 前端 TypeScript/Vite 生产构建通过，隔夜策略独立分包约 21KB（gzip约9KB）。
- 浏览器真实渲染验证通过：主导航、新路由、三个页签、八步节点、候选表、草案空态/参数矩阵、回测覆盖率与滚动窗口均出现在可访问树中。
- 浏览器首次截图发现深色页头文字对比度不足，已按审计规则打回修复；重启前端构建链并复截图后，标题、说明、数据时间和交易边界均达到清晰可读状态。
- 当前真实页面正确显示：预览模式、2只测试标的、分钟覆盖0.13%、历史股本0%、样本外0笔、仅观察；没有成功色伪装。
- 节点与三个页签可通过语义控件操作，候选证据按钮和节点输入/输出弹窗具备可访问名称。

**审计结论：通过。** 已闭环视觉重大缺陷，可进入最终端到端验收。

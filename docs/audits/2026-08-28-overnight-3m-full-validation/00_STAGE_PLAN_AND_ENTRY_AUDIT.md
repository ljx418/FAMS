# 近三个月全量主板策略验证：执行计划与入口审计

日期：2026-08-28
状态：允许进入数据探测与实现；不允许把三个月结果表述为长期有效性证明。

## 用户目标与冻结口径

- 验证信号窗口：2026-05-28至2026-08-27。
- 数据获取窗口：至少覆盖2026-04-20至2026-08-28，用于20交易日预热及最后一个信号日的次日退出。
- “A股全量”按原策略第2步解释为全量主板策略宇宙；科创板、创业板、北交所不进入候选。
- 当前本地证券快照共5,849只，其中主板代码规则命中3,481只；最终分母以实际获取的逐日可交易股票池为准，若无法取得则必须披露当前列表导致的幸存者偏差。
- 结果等级最高为三个月短窗口研究证据，不修改 `overnight.evidence.v2` 的24个月/300笔冻结样本及3–6个月前向门槛。

## 子阶段与验收标准

### A. 数据可用性探测

1. 使用项目既有BaoStock真实数据服务探测5分钟、日线、交易状态、ST、换手和复权字段。
2. 明确1分钟成交、点时总股本/总市值、公司行为、沪深300及第二数据源的实际可用性。
3. 任何缺失字段不得静默替换；代理字段必须命名为proxy并失去正式晋级权。

### B. 全量增量采集

1. Bronze原始响应不可变，Silver按主键去重；中断后可按请求哈希幂等续跑。
2. 全市场任务必须携带显式确认字符串；磁盘安全门槛不低于25GB。
3. 输出请求总数、成功/空数据/失败、行数、证券数、交易日、重复与无效OHLCV计数、存储和耗时。
4. 对失败请求有限重试并保留失败清单，不以“命令完成”冒充“数据全量”。

### C. 三个月策略回测

1. 八步门禁逐项输出输入、通过数和淘汰数；禁止未来函数。
2. 每日按冻结排序最多3只，单票10%、策略30%、100股整数手和现金约束。
3. 报告基础、2倍、3倍交易成本；与简单基线、匹配基线和沪深300比较。
4. 报告成交笔数、月份、平均净收益、PF、胜率、最大回撤、月度集中度及分块Bootstrap区间。
5. 若缺精确1分钟成交、点时总市值或公司行为，则正式结论必须为 `data_insufficient`；可同时报告明确标注的5分钟代理敏感性结果。

### D. 真实性与PRD复核

1. 对随机证券/交易日复查原始响应、Silver与Gold行数及哈希链。
2. 幂等重跑不得增加重复记录或改变同源结果。
3. 运行后端测试、构建和浏览器证据工作台复验。
4. 独立落盘最终事实、偏差、代价和停止原因。

## 开发前审计意见

| 风险 | 严重性 | 处置 |
|---|---|---|
| 三个月无法覆盖原24个月门槛 | 重大 | 单独标记为短窗口研究，不晋级 |
| 当前列表可能有幸存者偏差 | 重大 | 优先获取逐日股票池；取不到则阻断正式结论 |
| BaoStock仅提供5分钟而非精确1分钟 | 重大 | 5分钟仅做代理敏感性，正式成交门禁失败 |
| 日线换手可能包含收盘后信息 | 重大 | 只用前一交易日推导流通股本，禁止使用信号日收盘换手形成盘中条件 |
| 免费源无可靠点时总股本/总市值 | 重大 | 不用当前市值回填历史；无法取得则阻断第6步正式证据 |
| 全量请求耗时和外部限流 | 一般 | 幂等状态、进度、有限重试和可恢复续跑 |

上述风险均已有“阻断正式结论而非伪造通过”的闭环规则，无新增致命风险。用户已明确要求全量三个月数据，因此视为已授权本次高资源免费源采集；付费采购仍未授权。

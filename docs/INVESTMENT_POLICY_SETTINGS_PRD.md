# FAMS 统一投资政策设置 PRD

版本：1.0  
状态：已实现并通过自动验收；用户真实政策待配置与显式激活  
更新时间：2026-09-22

## 1. 目标

FAMS 使用一个版本化投资政策统一解释三类策略的资金预算和风险边界：

1. 基金组合：默认占可投资资金 50%，内部使用“四资产均衡组合”，股指、债基、黄金、组合内现金各 25%。
2. 红利低波：默认占可投资资金 30%，保留股息质量、低波动、估值、动态价格区间和分红论点失效规则。
3. 行业 / 个股轮动：默认占可投资资金 20%，保留 RRG、均线、MACD、成交量、ATR 与趋势失效规则。

用户先填写独立备用现金下限。备用现金不属于上述三类策略，组合内部现金也不重复计入备用现金。

## 2. 用户控制权

- `50/30/20` 是首次草案默认目标，不是自动调仓指令。
- 每个策略桶的警示上下限由用户填写。
- 比例越界只展示、解释和告警，不自动再平衡，也不生成强制调仓。
- 政策只能通过“草案 -> 明确确认 -> 活动版本”发布；活动版本不可原地修改。
- 当前支付宝高防御 / 永久组合规则继续保留，只有用户显式激活新政策后才切换。
- 单标的覆盖只能写入草案，必须填写原因并随政策版本审计。

## 3. 风险语义

| 策略 | 默认风险语义 | 超限行为 |
| --- | --- | --- |
| 基金组合 | 回撤复核、配置偏离和投资论点失效；不使用机械价格止损 | 告警，不自动卖出 |
| 红利低波 | 分红质量与动态价格区间共同失效 | 阻止新增风险草案，既有仓位只告警 |
| 行业 / 个股轮动 | ATR、MA30、RRG、MACD 和数据时点失效 | 阻止新增风险草案，既有仓位只告警 |

单标的和行业上限按总资产口径计算。已超限持仓不会被系统自动处理，但后续新增买入研究草案必须被阻断。

## 4. 实现实体

- `InvestmentPolicyVersion`：不可变活动版本与可编辑草案。
- `InvestmentPolicyAssetOverride`：单标的覆盖与理由。
- `InvestmentPolicyEvaluationSnapshot`：真实持仓在指定政策下的不可变评估。
- `investmentPolicyService`：合同校验、激活、真实持仓评估和新增风险容量。
- 激活、旧版本替换和不可变评估快照在同一数据库事务中提交；数据库部分唯一索引限制每用户同时只有一份草案和一份活动政策。
- 新版本草案继承当前活动版本的单标的覆盖，并在新版本下保留继承来源。
- `/api/v1/investment-policy/*`：政策读写、显式激活、评估与覆盖接口。
- `/investment-policy`：普通用户投资政策工作台。

## 5. 验收门槛

1. 真实持仓评估必须展示备用现金、三桶当前比例、目标比例、用户警示区间、单标的和行业敞口。
2. 目标比例合计必须等于 100%；四资产内部权重必须等于 100%。
3. 备用现金、三桶警示区间和组合回撤复核线未填写时禁止激活。
4. 活动政策不可原地修改；显式激活新版本后，旧版本标记为 `superseded`。
5. 比例漂移只能产生 `warning_only`，不得创建调仓或订单。
6. 单标的或行业容量耗尽后，轮动网格和红利低波人工草案均不得继续生成新增买入权重。
7. 使用真实 `default` 用户持仓运行 `npm run test:investment-policy`，并证明持仓和交易总数不变。
8. 固定保持：

```text
formalTradingUnlocked=false
autoTradeUnlocked=false
canCreateOrder=false
orderCreateAllowed=false
```

9. 红利低波行业上限必须与全局行业上限分别评估；缺少行业事实时不得伪造聚合，且必须阻断该标的的新增风险草案。
